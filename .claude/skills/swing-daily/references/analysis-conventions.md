# 定性分析の共通規約（swing-daily / analyze-news / analyze-filings / interpret-screening 共通）

このリポジトリの定性分析テキストは、生成後に ingest 側の機械検査を通る。
検査に落ちた銘柄は **リトライされず、その銘柄の定性セクションが縮退表示される**。
つまり規約違反は「あとで直せる指摘」ではなく「その日の分析が消える」ことを意味する。

各規約には **AC 番号**（AC1〜AC16）が振ってある。番号は安定した識別子であり、
専門家の自己点検・統括の統合レビュー・違反報告はすべてこの番号で参照する。

## AC チェックリスト（一覧）

## 原則: 判断はコード、叙述は分析

### AC1: 決定論的出力を再計算・上書きしない

スクリーニングのスコア・ランキング・リスク制約は決定論的な Python の出力。
**再計算・上書き・言い換えによる修正をしない。** 数値はそのまま引用する。

### AC2: 分析が足すのは叙述と推奨だけ（最終判断は人間）

分析側が足すのは「その数値が何を意味しうるか」の叙述と、定性情報に基づく
**推奨**（proceed / skip）だけ。
最終的な売買判断は常に人間が行う。分析は意思決定支援であって指示ではない。

## CON-03 準拠ルール

### AC3: 断定的売買指示の禁止

以下のような表現を、どのテキストフィールドにも書かない（機械検査あり）。検査は
Unicode NFKC 正規化後に行うため、全角英数などで表記を変えても回避できない。

- 日本語: 買うべき / 売るべき / 今すぐ買う / 今すぐ売る / 買いです / 売りです /
  強く推奨 / 購入すべき / 売却すべき / 購入してください / 売却してください /
  買い推奨 / 売り推奨 / 購入せよ / エントリーしてください /
  ポジションを閉じなさい
- 英語: you should buy / you should sell / buy now / sell now / must buy /
  must sell / recommend buying / recommend selling / strong buy / strong sell /
  please sell immediately

このリストは **例示であって網羅ではない**。禁止フレーズ表の正本は ingest 側の
CON-03 検査モジュール（`src/swing_copilot/analysis/` 配下）。表に載っていなくても、
読者に売買行動を命じる文は書かない。

### AC4: 命令形の禁止

「〜せよ」「〜しなさい」「〜してください」といった、読者への行動指示の命令形を
使わない。引用・否定の文脈で禁止表現を使う場合も、機械検査は安全側で違反として
扱うため、その表現自体を出力しない。書くのは観察と条件付きの解釈まで。

- NG: 「決算前にポジションを閉じてください」
- OK: 「決算発表が as_of の 2 営業日後に予定されており、イベントリスクが高い期間にあたる」

### AC5: 根拠なき心理・行動診断の禁止

投資家心理・経営陣の心理状態・市場のパニックといった、検証不能な心理／行動の
断定を書かない（機械検査あり）。「動揺」「パニック」「狼狽」「投資家心理」
「panic」「investor sentiment」「management is anxious」等のキーワードは、
同一テキスト内に次の **4 つすべて** が揃っている場合にのみ許容される。

1. hedge 表現（AC12 が挙げるもの。`可能性` / `考えられる` / `示唆` / `と読める` /
   `入力の範囲では` / `possible` / `possibly`）
2. パーセンテージ（例: `12%`）
3. 実績マーカー（`実績` / `actual`）
4. 計画マーカー（`計画` / `予想` / `planned` / `forecast`）

4 つのうち 1 つでも欠けると、その銘柄の定性セクション全体が
`copilot-ingest-analysis` に fail-closed で withhold される（リトライなし）。
迷ったら心理に言及せず、観測可能な事実だけを書く。

- NG: 「投資家心理が悪化している可能性がある」（2〜4 が欠落）
- NG: 「実績は計画を 12% 下回った。投資家心理は悪化している」（1 が欠落）
- OK: 「実績が計画を 12% 下回っており、投資家心理が悪化した可能性がある」
- OK: 「出来高が 20 日平均比 +180% に急増した」（観測事実のみ）

## provenance ルール

### AC6: すべての fact に非空かつ部分集合の source_ids、かつ本文からの逐語引用 evidence_quote

**すべての fact は入力の `source_id` を引用する。** `source_ids` は非空で、
かつその銘柄の入力に実在する ID の部分集合でなければならない。

加えて、すべての fact は `evidence_quote`（正規化後 12〜300 字の逐語引用）を持つ。
`evidence_quote` は、その fact が引用する `source_ids` のいずれかの本文（ニュースなら
`headline` ＋ `summary`、開示なら入力の `text`、カレンダーイベントなら `title` ＋
`summary`）に実際に含まれる文字列でなければならない。ingest 側の照合は Unicode
NFKC 正規化・全角/半角記号統一・空白畳み込み・大小無視のうえで行うため表記ゆれは
吸収されるが、**言い換え（パラフレーズ）は一致とみなされない**。`source_ids` が
「そのIDが自分の銘柄に供給されている」ことしか証明しないのに対し、
`evidence_quote` は「自分がその本文を実際に読んだ」ことを証明する。正しい
`source_id` を申告しながら別銘柄の本文を読んで書いた fact は、引用できる逐語箇所が
存在しないためここで検出される。`VerdictReason` には `evidence_quote` は無く、
引き続き空の `source_ids` を許す。

### AC7: source_id を推測・生成・整形しない

ID を推測・生成・整形しない。入力 JSON の文字列をそのままコピーする。

### AC8: 入力に無い情報を書かない

**入力に無い情報を書かない。** 事前知識にある企業情報・株価・決算数値を
補完してはいけない。入力テキストに書かれていない事柄は「入力からは判断できない」と書く。

### AC9: 複数ソースに支えられる fact は該当 ID をすべて列挙

1 つの fact が複数ソースに支えられるなら、該当する ID をすべて列挙する。

### AC10: 決定論的入力のみの理由は空リスト可、facts は常に非空

決定論的入力（スコア、リスク制約、market_regime）のみに基づく記述には
引用すべき source_id が無いため、`verdict.reasons` では空リストにできる。
ただし `facts` は常に非空の `source_ids` が要る（＝テキスト由来でない内容を
facts に混ぜない）。

## facts / interpretation の分離

### AC11: facts / interpretation / flags の役割分離

| フィールド | 書くもの | 書かないもの |
|---|---|---|
| `facts` | 入力テキストに明示されている事実。数値・日付・文言 | 推論、評価、見通し |
| `interpretation` | その事実が示唆しうること（hedge 付き） | 新しい事実、入力に無い数値 |
| `risk_flags` / `red_flags` / `concerns` | 懸念点の短い列挙 | 行動指示 |

facts に評価語（「好調」「悪化」）を混ぜない。facts は「売上高は前年同期比 +12%」、
interpretation は「成長率は前四半期の +8% から加速している」。

## hedge 表現の使用

### AC12: hedge 表現を付ける（facts を除く）

interpretation・risk_flags・screening_assessment・verdict.reasons は
断定を避け、hedge を付ける。

- 使う: 「〜と考えられる」「〜の可能性がある」「〜を示唆しうる」「〜と読める」
  「入力の範囲では〜」
- 避ける: 「〜は確実だ」「〜に違いない」「必ず〜する」

ただし facts は入力に書かれた事実そのものなので hedge は不要（余計な hedge は
かえって事実と解釈の境界を曖昧にする）。

**AC5 との関係**: ここに挙げた hedge 表現は機械検査（`analysis/safety.py` の
`_HEDGE_PATTERN`）と同期している。AC5 のキーワード（「投資家心理」等）を含む
テキストでは、この hedge に加えて数値根拠 3 点も必要になる（AC5 参照）。

## 網羅性についての正直さ

### AC13: 非網羅である旨を明記する

開示分析の `red_flags`、ニュースの `risk_flags` は **重要度優先の抜粋であって
網羅ではない**。長文を分割して読んだ場合や、入力が一部しか無い場合は、その旨を
`interpretation` に明記する（例: 「本分析は提供された 10-Q 抜粋に基づくもので、
リスク要因の網羅ではない」）。

### AC14: 入力が空・極小なら無理に内容を作らず null / []

入力が空・極端に短い場合は、無理に内容を作らず「該当テキストなし」として
`null` / `[]` を返す。

## 検査は自分の外にある

### AC15: 検査を通すための書き換えをしない

ingest の CON-03 検査・provenance 検査は、この規約を守れているかの最終確認であって、
分析側の一次防衛線ではない。「機械検査が通ればよい」という書き方（禁止語を言い換えて
実質的に売買指示をする等）は規約違反である。

## 数値の整合

### AC16: text の数値は evidence_quote の数値と桁まで整合させる

`evidence_quote` は「その本文を読んだ」ことしか証明しない。**引用は正しいのに、
それを日本語化した `text` の数値だけが誤っている**ケース（2026-08-11 の run で
`3,495,296`＝千ドル単位を「35億9,530万ドル」と書いた例。Issue #131）は、逐語一致の
検査では原理的に検出できない。

- `text` に数値を書くときは、その数値が `evidence_quote` の中のどの数値から
  導かれるのかを**必ず対応付けてから書く**。対応する数値が引用に無いなら、
  引用を数値が含まれる範囲へ取り直すか、その数値を書かない
- **単位変換は 1 桁ずつ検算する。** 開示本文の表は多くが `(in thousands)` で、
  `3,495,296`（千ドル）＝ 34億9,530万ドル。プレスリリース文は `$3.50 billion` の
  ように丸められていることがあり、丸めた値をそのまま `text` の細かい桁に
  持ち込まない
- 前年同期・前四半期を並べて書くときは、**各行を個別に**引用と突き合わせる。
  1 行だけ変換を誤る事故が実際に起きている
- 引用に無い数値（自分で計算した増減率など）を `text` に書くなら、その計算元の
  数値がどちらも引用に含まれていることを確認する

ingest 側は `text` と `evidence_quote` の双方に**単位・通貨の付いた数値**がある fact に
限り、10 のべき乗（千 / 百万 / billion / million / 億 / 万）を跨いで到達できるかを
機械的に照合し、到達できない数値をログに**警告**として出す。この検査は fail-closed
ではない（誤検知で銘柄を落とさないため）ので、**警告が出ないことは正しさの証明に
ならない**。年号・四半期・比率・株数のような単位の付かない数値は検査対象外であり、
最終的な検算責任はこの AC を守る分析側にある。
