# 00. 人間の下準備チェックリスト（swing-copilot）

## 目的

本ドキュメントは、swing-copilot プロジェクトの実装（Claude Code の `/goal` による自律実装）に着手する前に、**人間しか実施できない作業**（アカウント作成、APIキー取得、規約同意、支払い設定、運用習慣の合意等）を洗い出し、抜け漏れなく完了させるためのチェックリストである。

## 前提

- 対象フェーズ: 主に P0（人間の下準備、所要目安 0.5日）。一部項目は P3・P4 で実施するため、その旨を明記している。
- 実施者: 発注者本人（日本在住の個人投資家、Python可）。
- 本チェックリストの完了をもって P1（基盤構築）の着手条件を満たす。P3向け・P4向け項目はそれぞれのフェーズ開始前に完了していればよい。
- 各項目には「手順概要」「所要時間目安」「完了確認方法」を付す。

---

## チェックリスト

### P0: プロジェクト開始前に完了させる項目

- [ ] **1. Anthropic APIキー取得**
  - 手順概要: platform.claude.com でアカウント作成→課金設定（クレジットカード登録）→APIキー発行→使用上限アラートの設定（推奨）。
  - 所要時間目安: 20分
  - 完了確認方法: 発行された `ANTHROPIC_API_KEY` を手元に控えている。ダッシュボード上で使用上限アラートが設定済みであることを確認できる。

- [ ] **2. Finnhub 無料APIキー取得**
  - 手順概要: finnhub.io でアカウント登録→無料枠（60コール/分）のAPIキーを発行。
  - 所要時間目安: 10分
  - 完了確認方法: 発行された `FINNHUB_API_KEY` を手元に控えている。

- [ ] **3. FRED APIキー取得**
  - 手順概要: fred.stlouisfed.org でアカウント登録→無料APIキーを発行。
  - 所要時間目安: 10分
  - 完了確認方法: 発行された `FRED_API_KEY` を手元に控えている。

- [ ] **4. Discord Webhook URL発行（任意：通知が欲しい場合のみ）**
  - 手順概要: Discord通知はオプション機能（`settings.yaml`の`notification.enabled`はデフォルト`false`）であり、本項目は通知を使いたい場合のみ実施すればよい。使う場合は、Discordサーバーを新規作成（または既存サーバーの通知用チャンネルを用意）→対象チャンネルの「連携サービス」設定からWebhookを作成→Webhook URLを発行する。
  - 所要時間目安: 10分（使う場合のみ）
  - 完了確認方法: （使う場合）発行された Webhook URL（`DISCORD_WEBHOOK_URL`）を手元に控えている。テスト送信でメッセージがチャンネルに届くことを確認できる。

- [ ] **5. uv本体・既存リポジトリの確認と `.env` 作成**
  - 手順概要: `uv --version` でuv本体を確認する。プロジェクトは既に`/Users/masuyama/ghq/github.com/tomada1114/swing-copilot`へuv-templateから作成され、Git初期化と設計文書のコミットまで完了しているため、テンプレートの再コピーや`git init`は行わない。プロジェクト直下に `.env` を作成し `ANTHROPIC_API_KEY`, `FINNHUB_API_KEY`, `FRED_API_KEY`, `EDGAR_IDENTITY` を記載する（`DISCORD_WEBHOOK_URL` は項目4で通知を使う場合のみ）。`.env` が `.gitignore` 対象であることを確認する。
  - 所要時間目安: 20分
  - 完了確認方法: `uv --version` と既存リポジトリ内の`just lint`/`just test`が実行できる。`.env` に必要な値が記載され、`git check-ignore .env`で追跡対象外と確認できる。値そのものはログへ出さない。

- [ ] **6. SEC EDGAR用 identity文字列の決定**
  - 手順概要: SEC EDGARのAPI利用規約で必須とされる User-Agent ヘッダーの値を決定する（氏名またはアプリ名＋連絡先メールアドレスの形式）。
  - 所要時間目安: 5分
  - 完了確認方法: `氏名またはアプリ名 連絡先メールアドレス` の形式の文字列が確定し、`.env`の`EDGAR_IDENTITY`に設定されている。

- [ ] **7. 証券口座の確認**
  - 手順概要: 既存の米国株取引可能な証券口座（SBI証券・楽天証券等）があることを確認する。本システムは発注を自動化しないため、証券会社APIの申請は不要。
  - 所要時間目安: 5分
  - 完了確認方法: 米国株の発注が可能な口座が既にあることを確認済み。

- [ ] **10. 予算承認**
  - 手順概要: 試作期（P1〜P2）は月$5以内（LLM費のみ）、本番運用（P3〜）は月$25以内という上限をあらかじめ承認する。拡張時のFMP（$59/月）利用は任意判断であることを確認する。LLMモデルはデフォルトでニュース要約・決算書解釈とも最安のHaikuを使用する構成のため上限内に収まりやすい（決算書解釈の精度を優先してSonnet等へ切り替える場合はコストが上がる点に留意する）。
  - 所要時間目安: 5分
  - 完了確認方法: 上記の予算上限に同意している。

### P3開始前に完了させる項目

- [ ] **9. 毎朝のレポート確認・判断記録の時間確保**
  - 手順概要: ペーパートレード検証期間（3ヶ月以上）中、毎朝5〜10分程度、日次レポートを確認し、シグナルに対する判断（見送り／仮想エントリー等）を記録する運用習慣について、自分自身と合意する。
  - 所要時間目安: 5分（合意のみ。実運用は日々継続）
  - 完了確認方法: 毎朝の確認作業をP3期間中継続する意思を明確にしている。

### P4開始前に完了させる項目

- [ ] **8. EODHD契約判断とAPIキー登録**
  - 手順概要: P3のペーパートレード結果を踏まえ、EODHD All World EOD（$19.99/月、調整済み株価＋上場廃止銘柄API）への契約要否を判断する。契約する場合はAPIキーを取得し、`.env`へ`EODHD_API_KEY`として追記する。契約前に、利用予定プランで delisted（上場廃止銘柄）APIが実際に使えるかをEODHDサポートへ事前確認する。
  - 所要時間目安: 30分（サポート回答待ちを除く）
  - 完了確認方法: 契約要否の判断が下されている。契約する場合はAPIキーが発行され、delisted API利用可否がサポートから明示的に回答されている。

## 注意事項

- 本チェックリストの項目1〜3・5〜7・10（P0分。項目4は通知を使う場合のみ）が未完了でも、オフラインfixtureによるP1〜P2実装と検証は進められる。実キーを用いるlive canaryは必要な`.env`値が揃うまで縮退終了とし、キー不足を理由にテストを変更しない。
- S&P500構成銘柄リストのスナップショット（`config/universe_snapshot.csv`）はリポジトリに同梱されない。初回のWikipedia取得が成功した時点で自動生成され、以降の実行ではオフライン時・取得失敗時のフォールバックとして使われる。そのため初回実行時はWikipediaへのネットワークアクセスが必要になる。
- APIキー・Webhook URLはいかなる場合もリポジトリのコードや設定ファイルにコミットしないこと。ローカルの`.env`（`.gitignore`対象）で管理する。
- 項目9（毎朝の運用習慣）は形式的なチェックで終わらせず、実際にP3期間中継続できるかどうかを事前に現実的に見積もること。運用負担によるモチベーション枯渇はプロジェクトの主要リスクの一つである。
- 項目8（EODHD契約）はP4判断の前提となるため、P3終了間際になって初めて着手するのではなく、P3後半で余裕を持って準備を進めることが望ましい。
