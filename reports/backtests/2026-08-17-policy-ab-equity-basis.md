# --policy A/B と R1〜R5 の equity 基準での読み直し（2020-01-02 .. 2026-07-30）

Issue #200。#184（PR #199）で入った本番リスクゲート注入（`--policy`）と
equity 基準サイジングを、同一期間・同一候補ストリームで実走した結果である。

この文書は 2 つのことをする。

1. `copilot-backtest --policy none,regime,regime+risk` の 3 アーム比較
   （「レジームゲートを入れたら成績は良くなったのか」への初めての実測回答）
2. `reports/backtests/2026-07-30-strategy-comparison.md` の R1〜R5 を
   equity 基準で走らせ直し、どの結論が変わり、どれが変わらないかを明記する

**採用・設定変更は一切行っていない。** `docs/08_architecture_review_2026-08.md`
§5 原則 3（点推定だけで設定を変えない）に従い、この文書は判断材料であって

読み取れる事実:

- **レジームゲートが支配的**。`CASH_PRIORITY` によるブロックは 535 セッション
  （1,652 立会日の約 32%）で発動し、候補 3,790 件を落としている。
  レジーム判定の入力は SPY/QQQ/^VIX だけで建玉に依存しないため、ある日の
  レジーム判定そのものは 3 アームで同一である。`regime` と `regime+risk` で
  件数がわずかに違う（3,790 / 3,798、535d / 534d）のは、ゲートまで到達する
  候補の数（`already_held` で先に落ちる分）がアームごとに違うことによる。
- **サーキットブレーカーは 2 番手**。`regime+risk` でのみ有効で、132 セッション・
  候補 819 件をブロックする。`_block_reason` の優先順位は
  regime → circuit_breaker → earnings → heat → sector なので、この 819 件は
  「レジームでは落ちなかったがブレーカーで落ちた」件数である。
- **セクター上限は 93 件（57 セッション）、portfolio heat は 4 件（2 セッション）**。
  どちらも「効いているが支配的ではない」。heat 6.0% と sector 30% は
  現状の 10 銘柄・equity 基準サイジングではほとんど拘束しない。
- **earnings ゲートは 0 件**。これは設定の問題ではなく、シミュレータに
  時点整合な決算カレンダーが無いため `earnings_guard_fn` を渡しておらず、
  構造的に inert である（Issue #200 の注意書きどおり）。**この A/B は
  `risk.earnings_block_business_days` について何も言っていない。**
- **`insufficient_cash` が none で 1,566 件（326 セッション）**。equity 基準
  サイジングは建玉が増えてもサイズを縮めないので、10 枠を埋める前に現金が
  尽きる日がある。ゲートを入れると建玉数が減るためこの数は 13 件 / 10 件へ落ちる。

### 結論（第 2 節）

**この期間・このユニバースでは、レジームゲートは成績を改善しなかった。
悪化させた。**

- `none` の $158,390.88（+58.4%）に対し、`regime` は $94,800.95（-5.2%）、
  `regime+risk` は $85,576.40（-14.4%）。期待値は $59.28 → $-7.07 → $-20.37 と
  符号が反転する。
- 引き換えに得られるのは最大 DD の縮小だけで、それも `regime` の 37.80% →
  21.41% までである。**`regime+risk` は DD を 28.91% へ悪化させる**——
  ゲートを増やしたのに DD が増えるのは、サーキットブレーカーが下落局面で
  クールダウンに入り、その直後の反発局面で再エントリーできないためと読める
  （2020-03 と 2022 の V 字回復を含む期間であることに注意）。
  これは仮説であり、この走行だけでは確定しない。
- 平均投下資本は 83.99% → 51.57% → 49.06%。ゲートは「地合いの悪い日に
  現金を持つ」ことを確かに実行しているが、この 6.5 年ではその現金が
  機会損失として効いた。

**この結果を「レジームゲートを外せ」と読んではならない。** 期間が
2020-2026 という歴史的な強気相場（SPY 買い持ちが +150%）に偏っており、
「暴落を避ける装置」の価値はこの標本では原理的に測りにくい。読み取れるのは
「本番が実際に払っているコストの大きさ」であって、「ゲートが無価値である
こと」ではない。設定変更は行わない。

## 3. equity 基準そのものが何を変えたか

`avg_invested_pct` は #184 で初めて計器化された値で、旧 cash 基準の
「10 銘柄満玉でも投下資本 ~65%」という推定を実測へ置き換える。

現行既定（R2 構成、`--policy none`）の実測は **83.99%**。R1 81.71%、
R3 83.08%、R4 87.57%。つまり新基準ではポートフォリオはほぼ常に満玉であり、
旧基準の「常に 3 分の 1 が現金」という前提はもう成り立たない。

これが最大 DD の水準を丸ごと押し上げている（旧 20〜22% → 新 33〜38%）。
**旧レポートの DD の数字は新基準では読めない。**

### 旧列と新列の差は「サイジング基底の変更」だけではない

正直に書く。この old/new 比較は単一変数の対照実験ではない。旧レポートの
実行（2026-07-30）以降に入った変更が同時に効いている:

- **サイジング基底 cash → equity**（#184 / PR #199）。狙っている差。
- **`price_history_lookback_days` の統一**（#186 / PR #198）。バックテストが
  スクリーニングへ供給する履歴長が変わったため、候補列そのものが動きうる。
- **価格・ファンダの再取得/訂正**。バーは 2026-08-14 まで伸び、既存行にも
  訂正が入りうる。ベンチマーク最終値が $250,155.32 → $250,155.31 と 1 セント
  ずれているのはこの系統の差である（結論に影響しない大きさ）。
- **`exit_atr_period` の配線**（#194 / PR #202）は**数字を動かさない**。
  旧実装のハードコード `ATR_PERIOD = 14` と現行 `settings.backtest.exit_atr_period: 14`
  が同値のため。

したがって trade_count が default / minervini 系の全構成で 1〜3% 減っている
こと（R5 は 70 件で不変）をサイジング変更だけに帰属させることはできない。
一方、**同一走行内の列間比較（第 2 節の 3 アーム）と、同一コード・同一データ
で走った新列どうしの R1〜R5 比較は対照が取れている。**

### 結論が変わるもの / 変わらないもの

**変わらない:**

1. **構成の優劣順位（期待値）は不変**。旧 R5 > R4 > R2 > R3 > R1、
   新 R5 > R4 > R2 > R3 > R1。順位の入れ替わりは 1 つも起きていない。
2. **R2 採用（`band_atr_multiple: 2.0`）の根拠は維持され、むしろ強まる**。
   R1 → R2 の期待値は旧 $12.65 → $35.37（2.8 倍）、新 $9.18 → $59.28（6.5 倍）。
   PF 1.034 → 1.178、Sharpe 0.161 → 0.472 も同方向。
   `docs/04_detailed_design.md` の採用記述（§ R2 採用）は結論として有効である。
   ただしそこに書かれた「DD 同等（21.08% → 21.82%）」という数値そのものは
   旧基準の値であり、新基準では 35.58% → 37.80%（+2.2pt）と読み替える。
   「同等」という質的判断は維持される。
3. **R3 に R2 からの上積みは無い**。旧 $34.84 vs $35.37、新 $54.66 vs $59.28。
   どちらの基底でも R3 は R2 をわずかに下回る。`score_weights.atr_pct` を
   0.0 に据え置く判断は変わらない。
4. **全構成がベンチマーク（SPY 買い持ち $250,155.31）を下回る**。最良の R4 でも
   $187,347.47。旧レポートの結論と同じである。
5. **`max_hold_days` は結果に効いている**。binding rate は R1 26.47% /
   R3 27.72% / R4 25.81% / R5 31.43% で、いずれも旧レポートと同じ 25〜31% 帯に
   あり、事前基準の「5% 未満なら感応なし」を大きく上回る。R2 の binding rate は
   複数アームのレポート出力が決済理由内訳を出さないため取得していない
   （第 6 節の後追い項目）。

**変わる:**

6. **最大 DD の水準は読み直しが必須**。R1〜R4 で旧 20〜22% → 新 33〜38%。
   投下資本が ~65% 前提から実測 82〜88% へ上がった直接の帰結であり、
   旧レポートの DD を「この戦略のリスク」として引用してはならない。
7. **「ベンチマークに勝てないのは現金を遊ばせているからかもしれない」という
   逃げ道が消えた**。旧レポートは投下資本 ~65% を前提に議論していたが、
   新基準の実測は 83.99%（R2）である。**ほぼ満玉で運用してなお SPY 買い持ちに
   $158,391 対 $250,155 で負けている。** 旧結論（買い持ちに勝てていない）は
   維持されるどころか、説明可能性を 1 つ失って強くなった。
8. **R4 の「全構成で最良、しかも DD も最小」の後半が弱まる**。旧 R4 は
   Sharpe 0.721・PF 1.339 で他を明確に引き離していたが、新基準では
   Sharpe 0.546・PF 1.210 と R2（0.472 / 1.178）との差が縮む。期待値と
   final_equity での首位は変わらない。DD は依然として R1〜R4 中で最小
   （33.20%）である。
9. **R5（vcp_breakout）の高い指標は「ほとんど何も建てていない」ことの裏返し
   だと明示できるようになった**。`avg_invested_pct` は **6.20%**。PF 1.951 も
   DD 4.39% も、資本の 94% が現金である portfolio の数字である。他構成と
   final_equity や DD を横並びにするのは誤読であり、旧レポートには
   この区別を付ける計器が無かった。

## 5. 限界

- **単一パスの点推定である。** 標準誤差も信頼区間も付いていない。
  `docs/08_architecture_review_2026-08.md` §5 原則 3 により、この数字だけで
  config を変えることはしない。
- **期間バイアス。** 2020-2026 は SPY が 2.5 倍になった期間であり、
  「守りのゲート」を評価する標本としては最も不利な部類に属する。
- **earnings ゲートは inert。** 第 2 節参照。決算カレンダーの時点整合な
  供給が入るまで、この A/B は決算ブロックについて何も測っていない。
- **生存者バイアス。** 以下は `backtest/engine.py::SURVIVORSHIP_BIAS_NOTE` の
  全文である。

> This backtest applies one S&P 500 constituent snapshot to the entire
> period. It does not reconstruct day-by-day index membership; when
> historical membership is unavailable, the current universe is used.
> Removed or delisted symbols may be absent, overstating historical
> performance (survivorship bias).

現行ユニバースを全期間へ適用しているため、この比較は**構成間の相対**を
読むためのものであり、絶対的な期待収益の推定には使えない。

## 6. この走行で気づいた計器の不足（本 issue の対象外・未修正）

設定変更と同様、コード修正もこの文書では行っていない。事実の記載のみ。

- **複数アームのレポートは決済理由内訳と equity カーブ要約を出さない。**
  単一アームの出力（`render_markdown`）は `stop` / `max_hold` /
  `end_of_backtest`・binding rate・保有日数分位・ピーク/ボトムを出すが、
  `render_policy_comparison_markdown` は指標表とゲート表だけである。
  そのため第 4 節の R2 行に binding rate と equity カーブが無い。
- **`--db` を `bars/` の無いディレクトリへ向けると、全銘柄が「データ不足」の
  ゼロトレード走行になり、終了コード 0 でレポートが書かれる。**
  `--db PATH` は Parquet の格納先を `PATH.parent / "bars"` として一緒に
  上書きする仕様（`docs/04_detailed_design.md` に明記あり）だが、警告は
  「データ不足のためスキップ: <全銘柄>」というフェイルソフト表示に紛れる。
  本作業でも一度この形で 3 秒で「完走」した走行を作ってしまい、
  出力を読むまで気づかなかった。
